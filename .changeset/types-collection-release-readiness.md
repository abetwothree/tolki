Add `CollapsedObject<T>`, the object `collapse()` merges an object's or a list's items into, and `FlattenReach<T>` / `FlattenItemReach<T>`, every value `flatten()` may push at some depth for a value or below it, and for one item flattened, so never a container it unwraps. They are re-exported from the package root beside the other object-side helpers: `collapse()` in `@tolki/arr` and `@tolki/obj` types its result with `CollapsedObject`, and `flatten()` in `@tolki/arr`, `@tolki/obj` and `@tolki/collection`, and `dot()` in `@tolki/arr` and `@tolki/collection`, type their values with `FlattenReach` or `FlattenItemReach`. `CollapsedObject<{ a: { x: 1 }; b: { y: "s" } }>` is `{ x: 1; y: "s" }`, and `FlattenItemReach<number[][]>` is `number[] | number`. A type cannot tell a class instance from a plain object, so `FlattenItemReach` types a class instance item as walked, where `flatten()` keeps it whole. `objects.d.ts` also declares the types these and `SpreadArgs` are built from: `CollapseItem`, `CollapseEntries`, `CollapseRequired`, `CollapseAlwaysKeys`, `CollapseGuaranteed`, `CollapseKeys`, `CollapseValue`, `CollapseMerge`, `CollapseAnyValue`, `FlattenReachOf`, `SpreadRowItems` and `SpreadZip`. A `.d.ts` module exports every top-level type, so they can be imported from the package root, but they are implementation details of the helpers above, not supported API.

Add `SpreadArgs<TRow, TKey>`, the arguments a `mapSpread` or `eachSpread` callback receives for one row: the row's items, then its key. Rows of one fixed length (a tuple, or a union of tuples of the same length) spread position by position, so a callback may leave off the key. Any other row spreads as a list in which every argument may be an item or the key, because the key's position varies: a list of open length, the values of a plain object or a Map row, each of which stands for a PHP array, and a Collection-like row's items, read through `all()`. A scalar, a function, or a Set, Date, RegExp or Promise row is passed whole. A null row hands on no items, since PHP's key append turns it into an empty array, so its key alone follows. A type cannot tell a class instance from a plain object, so `SpreadArgs` spreads a class instance row's values, where `mapSpread` passes the instance whole. `SpreadArgs<[number, string], "x">` is `[number, string, "x"]`, and `SpreadArgs<string[], number>` is `(string | number)[]`. `mapSpread` in `@tolki/arr` and `@tolki/obj`, and `eachSpread` and `mapSpread` in `@tolki/collection`, type their callbacks with it.

Widen `SortSpec<TValue>`'s comparator to answer `number | boolean`. PHP 8 deprecates a comparator that answers a bool but still sorts by one, and the sort helpers in `@tolki/arr`, `@tolki/obj` and `@tolki/collection` now read such an answer as PHP's `usort()` does, so the type admits it. Every value that satisfied `SortSpec` before still does.

Deprecate `ProxyTarget` and `PropertyName`: nothing in the @tolki packages reads them now that `@tolki/collection` has dropped its unused item proxy, and the next major release removes them.
