---
"@tolki/utils": minor
---

**Breaking.** Fix `compareValues(a, b)` for an empty plain object ordered against `null` or a boolean: it now casts to `false`, as PHP casts the empty array it models, where it was read as truthy. `compareValues({}, null)` and `compareValues({}, false)` are `0`, where they were `1`, and `compareValues({}, true)` is `-1`, where it was `0`, matching PHP's `[] <=> null`, `[] <=> false` and `[] <=> true`; the array spelling already agreed. Two further divergences from PHP remain: an array against a scalar keeps JavaScript's coercion, and a `Date` against an array or a plain object keeps the entry-count rule. `operatorMatch`'s ordering operators order through `compareValues`, so they follow: `operatorMatch({}, '<', true)` now holds and `operatorMatch({}, '>', null)` no longer does, which leaves `operatorMatch` one divergence from PHP, an array or a plain object ordered against a scalar.

**Breaking.** Fix `isPhpFalsy(value)`: it follows PHP's truthiness for objects. Every PHP object is truthy, so a `Date`, a `RegExp` or a class instance is now truthy however empty, where it was falsy for carrying no own enumerable keys. An empty array or plain object is still falsy, since each models a PHP array, and a `Map` or a `Set` stands in for one too: it is falsy exactly when empty, where a non-empty one was falsy before. A bigint is falsy when it is `0n`. `isPhpFalsy(new Date(0))` and `isPhpFalsy(new Map([[1, 'a']]))` are now `false`, where both were `true`, and `isPhpFalsy(0n)` is now `true`, where it was `false`. This is visible to every truthiness test in `@tolki/arr`, `@tolki/obj`, `@tolki/data` and `@tolki/collection`, which `isPhpFalsy` decides: a `filter()` called without a callback now keeps a `Date` or a class instance, as PHP's `array_filter()` keeps every object, and `Arr.toCssClasses({ active: new Date(0) })` is now `"active"`, where it was `""`. `compareValues` and `looseEqual` now cast to a boolean with this same rule, so an empty `Map` or `Set` ties `false` and `null` in `compareValues` and is loosely equal to them in `looseEqual`, as an empty array is.

**Breaking.** Fix `arrayableValues(items)`: it never unwraps a plain object as an Arrayable. A plain object models a PHP array, so it is data whatever members it has: one holding an `all`, `toArray` or `toJSON` function contributes that function among its values instead of the function's result. Only a class instance exposing one of those methods unwraps, as Laravel's `getArrayableItems()` unwraps only an `Enumerable`, `Arrayable` or `JsonSerializable` instance. `arrayableItems(items)` follows the same rule, returning such an object as it is, so every `diff*`, `intersect*`, `union`, `replace*` and `combine` in `@tolki/arr`, `@tolki/obj`, `@tolki/data` and `@tolki/collection` now keeps such an operand's own entries. `arrayableValues({ toArray: () => [1, 2] })` is now a one-item list holding that `toArray` function, where it was `[1, 2]`; `arrayableItems({ all: () => ({ a: 1 }) })` is now that object itself, where it was `{ a: 1 }`; and `Arr.diff([1, 2], { all: () => [1] })` is now `[1, 2]`, where it was `[2]`.

**Breaking.** Widen the comparators `createSortSpecComparator(resolve)` builds to answer `number | boolean`, where they answered `number`. A comparator descriptor, which `SortSpec` now lets answer a bool, is handed back as it is, and a bool answer is read as PHP's `usort()` reads it only where `phpSortComparator` reads the whole comparison. Code that used a built comparator's answer as a number must narrow it first.

Add `InvalidArgumentException` and `UnexpectedValueException` to the `exceptions` module, ports of the two PHP exceptions Laravel's collections and `Arr` throw, each thrown where Laravel throws it. `InvalidArgumentException` is thrown for an argument out of range: by `nth`, `random`, `shift`, `sliding`, `split` and `splitIn` in `@tolki/collection`, and by `random` and `shift` in `@tolki/arr` and `@tolki/obj`. It is also thrown for a value `Arr` refuses, in `@tolki/arr` and `@tolki/obj` alike: by `arrayItem` and `objectItem` (Laravel's `Arr::array()`), `boolean`, `float`, `integer` and `string` for a value of another type, by `push` for a non-array at the key, and by `from` for a scalar. Each of those sites threw a plain `Error` with the same message before. `UnexpectedValueException` is thrown for a value of the wrong type (`ensure`, `reduceSpread`). Each extends `Error`, names itself after its class and carries the message it is given, so a caller can tell them apart with `instanceof`, as PHP code does with `catch`.

Add `getCount()` to `MultipleItemsFoundException`: it answers the `count`, as Laravel's exception's `getCount()` does.

Add `phpComputedKey(value, options)`: the key a Laravel method stores for a value it computed, cast the way that method casts it. `true` and `false` become `1` and `0`, `null` and `undefined` become `""`, a float truncates and a canonical integer string becomes a number, as `phpArrayKey` casts them. Two options mirror the conversions only some Laravel methods apply first: `enumCases` reads an `@tolki/enum` case (a plain object with its own string `name` and its own string or number `value`) as its value, as `enum_value()` does, and `stringables` reads an object with its own `toString` as that string, as a `(string)` cast does; a `Date` never counts, since PHP's `DateTime` has no `__toString`. Any object left over, whether an array, a plain object, a `Date`, a `Map`, a class instance or a function, is a key PHP cannot store, so it throws `TypeError: Cannot access offset of type X on array`. X is the name `phpDebugType` gives: `array` for an array or a plain object, `Closure` for a function, which PHP reads as a closure, the class for any other object, and `object` for one with no class at all. The `invalid` option builds a different error for a method whose PHP throws another one.

Add `isEnumCase(value)`: whether a value is an `@tolki/enum` case, the shape `from()` and `cases()` build: a plain object with its own string `name` and its own string or number `value`. `phpComputedKey` reads such a case as its value when a method unwraps enum cases, and a caller can tell a case apart from an ordinary plain object with it.

Add `isIllegalOffset(value)`: whether a value is a key no PHP array can hold, which PHP throws a `TypeError` for wherever it reads or writes one: an array, a plain object, any other object, or a function, which PHP reads as a `Closure`. A string, a number, a boolean, `null` or `undefined` is not, since PHP casts each to a key. `phpComputedKey` asks it which keys to throw for.

Add `arrayKeyExistsError()`: the `TypeError` Laravel's calls to `array_key_exists` throw for such a key, `array_key_exists(): Argument #1 ($key) must be a valid array offset type`. Laravel calls the function from a namespace, where PHP runs its own argument check; code outside a namespace compiles it to an opcode that throws `Cannot access offset of type array on array` instead. `forget` and `except` in `@tolki/arr`, `@tolki/obj` and `@tolki/data`, `except` in `@tolki/collection`, `select` over an item PHP reads as an array in all four, and `groupBy`, `get`, `getOrPut`, `has`, `hasAny` and `pull` in `@tolki/collection` throw it for such a key, as their PHP does.

Add `hasOwnToString(value)`: whether a value is an object with a `toString` of its own rather than `Object.prototype`'s, which is how a PHP `Stringable` looks from JavaScript. A `Date` never counts, since PHP's `DateTime` has no `__toString`, and an array, a primitive or an object that only inherits `Object.prototype`'s `toString` does not either. `phpComputedKey`'s `stringables` option asks it which objects to read as their string.

Add `phpDebugType(value)`: a value's type, named as PHP's `get_debug_type()` names it. That is `null` (for `undefined` too), `int` for a number PHP holds as an int, `float` for any other (`NAN`, `-0` and an integer past PHP's int range such as `1e19` included), `string`, `bool`, `array` for an array or a plain object, `Closure` for a function, and an object's class name. An instance of an anonymous class is named after the class it extends, as `Parent@anonymous`, or `class@anonymous` when it extends none. A symbol, a bigint or an object with no class, which PHP has no type for, keeps its `typeof` name. The messages `ensure`, `sum`, keyed access and the callback checks in `@tolki/collection` throw name types with it.

Add `isPhpInt(value)`: whether a value is a number PHP holds as an int, an integer within its 64-bit range and never `-0`. `1e19`, `2 ** 63` and `-0` are floats in PHP, so `phpDebugType` names them `float`, and `resolveRangeSize` prints a range with such a bound as a float range.

Add `phpIntArgument(value, message)`: read a number PHP passes to an int parameter, which drops a fraction toward zero as PHP's coercion does. `NAN`, an infinity or a number outside PHP's 64-bit int range throws `TypeError(message)`, as PHP refuses such a float. `slice`, `take`, `chunk`, `multiply` and `percentage` in `@tolki/collection` read their counts with it.

Add `phpIntCast(value)`: a number cast to an int as PHP's `(int)` cast casts it, as PHP also reads a comparator's answer and the operands of `%`. The fraction is dropped, `NAN` and the infinities become 0, and a number past PHP's 64-bit int range keeps its low 64 bits, as PHP 8 does: `phpIntCast(1e19)` is `-8446744073709551616` and `phpIntCast(2 ** 64)` is 0. `phpSortComparator` reads a comparator's number with it, as do the `*Using` methods, `nth`, `split` and `splitIn` in `@tolki/collection`, so `nth(2 ** 64)` and `split(2 ** 64)` throw PHP's `Modulo by zero`.

Add `phpStringCast(value)`: a value cast to a string as PHP's `(string)` cast casts it, as `implode()` casts each piece and `.` its operands. An array, or a plain object or a `Map` standing for one, is `"Array"`. An object with its own `toString` is that string. Any other object or a function throws `Error: Object of class X could not be converted to string`, X as `phpDebugType` names it. A scalar is cast as `toPhpKeyString` casts it: `true` to `"1"`, `false` and `null` to `""`, a float to 14 digits. `implode` and `join` in `@tolki/collection` cast their pieces with it, as does `join` in `@tolki/arr` and `@tolki/obj`, which cast them with `String()` before: `Arr.join([1, [2, 3]], ',')` is `"1,Array"` where it was `"1,2,3"`, and `Arr.join([true, null], ',')` is `"1,"` where it was `"true,null"`.

Add `phpSortComparator(compare)`: a comparator for `Array.prototype.sort` that reads another comparator's answers as PHP's `usort()`, `uasort()` and `uksort()` read them. A number is cast to an int as `phpIntCast` casts it, so a fraction below 1, `NAN` or an infinity ties, and a number past PHP's int range keeps its low 64 bits: a comparator answering `1e19` for a greater item sorts backwards, as PHP's does, and one answering `2 ** 64` ties. A bool is deprecated in PHP 8 but still sorts: `true` is 1, and `false` asks again with the operands swapped, where `true` is -1. `sort` and `sortKeysUsing` in `@tolki/collection` read their comparators with it, as do `sortBy`'s comparators there and in `Arr.sort`, `Arr.sortDesc`, `Obj.sort` and `Obj.sortDesc`, which hand it the whole multi-key comparison as PHP hands `uasort()` its closure. Before, a bool comparator's order depended on how the engine's sort read `true` and `false` as 1 and 0, so it was unreliable: `collect([5, 3, 9, 1, 7, 2, 8]).sort((a, b) => a > b)` gave `[1, 2, 5, 3, 9, 7, 8]` and `Arr.sort([3, 1, 2], [(a, b) => a > b])` gave `[3, 1, 2]`. Both now sort as PHP does, to `[1, 2, 3, 5, 7, 8, 9]` and `[1, 2, 3]`.

Add `resolveTakeCount(count, size)`: how many items Laravel's `shift()` and `pop()` take for a count, one per item of the `range(1, min($count, $size))` they loop over. A fraction is dropped, and a `NAN` count takes every item, since PHP's `min()` answers `$size` over a `NAN`. A fraction below 2 that the items do not cap throws `range()`'s `ValueError` as an `Error`. `shift` and `pop` in `@tolki/arr`, `@tolki/obj` and `@tolki/collection` count with it, so both backings agree: `shift(2.5)` takes 2 items where a list took 3, `shift(NaN)` takes every item where it took none, `shift(1.5)` throws, and `pop(0.5)` pops nothing where a list or a record popped one item. A Map, which `@tolki/obj` now pops from in its insertion order, pops nothing for it either.

Add `resolvePadLength(size)`: the length `array_pad()` pads to, read as PHP reads its int parameter. A fraction is dropped. `NAN`, an infinity or a length outside PHP's int range throws `array_pad()`'s `TypeError`, and a length past PHP's maximum array size of 2^30 throws its `ValueError` as an `Error`. `pad` in `@tolki/arr`, `@tolki/obj` and `@tolki/collection` reads its size with it: `pad(7.5)` pads to 7, where a list threw `RangeError: Invalid array length` and a record padded to 8, and `pad(Infinity)` throws where a record never returned.

Add `resolveSpliceRange(size, offset, length)` and the `SpliceRange` type it returns, `{ start, count }`: the index `array_splice()` starts at and how many items it removes, the twin of `resolveSliceRange`. The offset and the length are read as PHP reads its int parameters, so a fraction is dropped before a negative one counts back from the end. `NAN`, an infinity or a number outside PHP's int range throws `array_splice()`'s `TypeError`. A `null` or `undefined` length runs to the end, as PHP's `?int` length reads null. `splice` in `@tolki/arr`, `@tolki/obj` and `@tolki/collection` resolves its window with it: `splice(1.5)` removes from index 1 to the end where a list stopped one short, `splice(-1.5, 1)` removes the last item where it removed the one before, `splice(NaN, 1)` throws where it spliced at 0, and `splice(1, null)` in `@tolki/arr` and `@tolki/obj` removes to the end where it removed nothing.

Add `resolveRangeSize(start, end, step)`: how many items PHP's `range()` makes room for from a start to an end by a step. It refuses what `range()` refuses, each with its `ValueError`'s message as an `Error`: a bound or a step that is `NAN` or infinite, a step of 0, a negative step on an increasing range, a step longer than the range, and a range that would hold 2^30 items or more, the maximum array size `resolvePadLength` keeps to as well. A range whose bounds and step PHP holds as ints counts whole steps. Any other range rounds its size half up, and `range()` then drops an item that rounding puts past the end: `resolveRangeSize(0, 1.5, 1)` is 3, where `range(0, 1.5, 1)` holds 2 items. The size message prints an integer range's figures as integers and a float range's as PHP's `%.1f` prints them: the exact value rounded to one decimal, an exact half to even, and a size that overflows as `inf`. `range`, `times` and `sliding` in `@tolki/collection` size themselves with it, so a range past the limit throws before it builds an item.

Document `typeOf(v)` as it behaves: it reports JavaScript's `typeof` name, except that an array reports as `"array"`, so `typeOf(null)` is `"object"`, not the `"null"` its example gave. The function itself is unchanged.
